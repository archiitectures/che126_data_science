# ChE126 Capstone — Codex Data Science Handoff

## Project background

This capstone studies **lithium-ion battery separator failure**, with an EV-battery focus. The main physical failure pathway of interest is:

**temperature / mechanical stress → pore collapse or separator shrinkage → melting / loss of isolation → internal short circuit → possible thermal runaway**

The project will be primarily computational, with simulations handled by a **separate initialization/agent**. This Codex instance should focus only on the **data science / ML / data-engineering layer** around those simulations and external separator-property data.

A major near-term goal is to build a usable dataset of separator properties from sources such as:
- research papers and supplementary data,
- manufacturer / industrial datasheets,
- patents,
- standards and testing documents,
- public materials/property databases where relevant.

Temperature-dependent measurements are especially valuable.

## Codex scope: data science only

Codex should own code for:

1. **Data ingestion**
   - Load CSV/JSON/XLSX or manually curated literature/patent tables.
   - Support adding simulation outputs generated elsewhere.
   - Preserve source/provenance metadata.

2. **Data cleaning + normalization**
   - Standardize units, material names, separator types, test conditions, and temperature.
   - Handle missing values and repeated measurements.
   - Keep raw and processed data separate.

3. **Canonical dataset/schema**
   Suggested fields where available:
   - `source_id`
   - `source_type`
   - `material`
   - `separator_type` (PE, PP, multilayer, ceramic-coated, etc.)
   - `thickness_um`
   - `porosity_pct`
   - `pore_size_um`
   - `temperature_C`
   - `thermal_conductivity_W_mK`
   - `melting_temp_C`
   - `shutdown_temp_C`
   - `shrinkage_pct`
   - `tensile_strength_MPa`
   - `elastic_modulus_MPa`
   - `permeability`
   - `electrolyte_uptake_pct`
   - `ionic_resistance`
   - `test_method`
   - `notes`
   - provenance fields such as DOI/patent/document/page/table.

   Exact schema can evolve as real data is collected.

4. **Exploratory analysis**
   - Property distributions and missingness.
   - Property-vs-temperature curves.
   - Comparisons across separator chemistries / constructions.
   - Outlier and inconsistency detection.
   - Correlations between physical properties and failure-related metrics.

5. **Simulation-data interface**
   - Define clean loaders/adapters for simulation outputs generated by the separate simulation code.
   - Simulation code itself is **out of scope**.
   - Prefer tidy/tabular outputs with run metadata and simulation parameters.

6. **Predictive / surrogate modeling**
   Once enough data exists:
   - regression for temperature-dependent properties,
   - prediction of pore-collapse / shrinkage / failure indicators,
   - surrogate models approximating expensive simulation outputs,
   - uncertainty estimation where practical.

   Start simple: baselines such as linear/polynomial regression, random forest, gradient boosting, or small neural nets only if justified by dataset size.

7. **Evaluation**
   - Train/validation/test splits that avoid leakage across near-duplicate materials or repeated measurements.
   - Report MAE/RMSE/R² for regression as appropriate.
   - Include uncertainty/error bars when source data supports them.
   - Prefer physically meaningful plots over benchmark-only metrics.

## Coding conventions

- Python-first, notebook-friendly workflow.
- Keep core logic in reusable `.py` modules; notebooks should mainly call library code for EDA/experiments.
- Prefer lightweight Python configuration over YAML.
- Use `pytest` for important preprocessing/model utilities.
- Do not silently overwrite raw data.
- Record units and provenance explicitly.
- Make pipelines deterministic where possible.

Suggested structure:

```text
project/
├── data/
│   ├── raw/
│   ├── interim/
│   └── processed/
├── notebooks/
├── src/
│   ├── ingestion/
│   ├── preprocessing/
│   ├── features/
│   ├── models/
│   ├── evaluation/
│   └── visualization/
├── tests/
└── outputs/
```

## Immediate priorities

1. Create the canonical schema and data-validation utilities.
2. Build loaders for manually curated literature/patent/property tables.
3. Build a normalized processed dataset with unit conversion and provenance.
4. Create an EDA notebook for temperature-dependent separator properties.
5. Define the interface expected from the separate simulation pipeline.
6. Only after the above is stable, add baseline predictive/surrogate models.

## Important boundary

**Do not implement the physical simulations here.** Another agent/setup will generate or manage those. Codex should treat simulations as an upstream data source and focus on turning external + simulated data into clean datasets, analyses, and models.
